# Buck Lab · AI 实验工作台

面向 ST4001 的 Buck 变换器分析原型：PLECS CSV → 波形检查 → L/C/R 辨识 → 留出验证 → DeepSeek 对话。采用 **GitHub Pages 静态前端 + Render FastAPI 后端**，本地也可以一条命令启动。

## 本地运行

左栏“会话检索”支持按问题检索当前会话全部已保存的用户消息和 AI 回答，不限最近十条，也不限四次实验分析。例如：“总结之前关于 GitHub 部署的讨论”“找出最早三条关于噪声的回答”。“填写检索问题”按钮在输入框为空时填入模板并选中主题占位符，替换主题后发送；已有草稿会保留。结果显示检索消息数、实际读取材料数，以及跳转原消息的按钮；失败回答不作为材料。

完整消息发送到本网站分析后端，在本次请求内按中英文关键词和中文双字词分块检索，仅将相关原文及出处交给已配置的 DeepSeek。普通聊天仍有最近十条上下文；模型还可以主动搜索旧消息、换词、分页和按消息 ID 继续读取长文。每次检索默认最多返回 8 条，可指定数量、最早或最近，单页最多 20 条；不是固定截取最后四条。长文返回命中片段及字符位置，不静默丢弃 8000 字符之后的内容。每次原文读取总预算 72000 字符，耗尽或仅覆盖部分记录时必须说明范围，不声称读完全部会话。此功能是本地关键词检索加模型分析，不能保证找出所有语义相关表述；可补充当时使用的关键词继续提问。

单独的历史问答检索不要求 CSV、当前结果或已保存实验存在，也不启动新辨识。明确同时要求“先辨识，再对比之前结果”时，仍按界面当前确认的配置执行，不能从历史回答推断配置。历史 AI 回答作为历史观点，不能当作本次重新计算的结果。新回答保存对应请求 ID；结果分析还保留方法、PWM 来源、结果 ID 和文件名，旧按钮分析兼容配对。元数据随会话保存同步，无数据库迁移。没有 AI 服务时仅显示本地检索原文，不冒充语义总结。需要同时部署前后端，无新增环境变量。

同一会话内每次完成辨识都会独立保存实验摘要（方法、实际使用的 PWM 来源、CSV 文件名及校验值、配置、预测参数、误差、诊断与该次真值对照）。左栏历史区域的“已保存实验”可查看记录。更改配置或上传另一份 CSV 只清空当前结果卡，不覆盖先前实验；摘要随会话在浏览器和后端合并同步，删除会话则一并删除。摘要不包含完整波形和逐轮训练数组，完整数据仍请导出 JSON 报告。

提问时，助手会收到当前会话各次实验的限定摘要：文件名/校验值、方法、PWM 来源、预测 L/C/R 及该次用户真值。后端按每次预测值重新计算 L/C 相对误差，不能跨实验沿用真值。数值实验摘要不包含原始 CSV、完整波形、逐轮训练记录、列映射或详细训练指标；历史对话检索则按上述规则提供相关原文或明确标记的片段。询问“对比这四次实验”时读取保存的摘要，不依赖当前结果卡、旧任务缓存或 CSV 在线状态，也不会重跑辨识；DeepSeek 不可用时提供本地对比表。摘要不含其他工况配置，助手不能据此假定各次工况完全相同。

更新后会尝试补回当前会话在后端缓存中尚存的已完成实验；旧缓存已经过期、进程已经重启或任务被淘汰时，无法自动还原此前未归档的结果。每会话最多同步 200 次实验摘要，仍受原有 8 MiB 会话档案上限约束，超限会提示保存失败而不会自动删除旧实验。本次新增存储字段和恢复接口需要同时更新前端与后端，无新增环境变量；Render 长期备份仍依赖既有持久磁盘配置。

**http://127.0.0.1:8000**


默认以中间对话区为主。左侧“导入波形”有折叠/展开按钮；选择或拖入 CSV 后自动读取、应用建议映射并显示右侧波形，请核对列与单位。参数辨识默认仅显示“进入参数辨识”，导入文件不会启动辨识。点击进入后，左侧展开基本信息，右侧显示波形与辨识结果；退出时保留数据、配置和结果。

“加载已有实验示例”仍加载内置 Case16A，右侧下拉按钮列出当前私有档案的历史 CSV，包括同一会话中先前被替换且仍保留的文件。列表结合浏览器与后端副本，按会话和文件内容去重，并显示来源会话日期及短编号。选择后校验文件内容并加载到当前会话，不切换对话或复制其他会话的配置。已删除会话、已清除代次的数据不再列出；文件无法恢复时保留当前数据并提示。列表不会访问其他同步恢复码的档案。

左栏“实验与历史”和右栏“波形与辨识结果”标题右侧的箭头可分别将整栏收起到侧边窄栏，再次点击即可展开；两栏可同时收起，为中间对话让出空间。收起保留数据、辨识设置和结果，不退出辨识或中断任务。右栏不再显示关闭按钮，需要退出辨识时使用左栏的“退出辨识”。手机窄屏下收为短标题栏，避免遮挡对话；标题和按钮提示同步支持中英文。

右上角的 **EN / 中文** 按钮即时切换界面语言，当前浏览器会记住选择。切换保留已上传数据、输入值、波形和辨识结果；已有对话、CSV 文件名/列名及原始后端诊断内容保留原文。

输入聊天草稿或编辑表单时，内容继续按原有机制保存到浏览器；自动完整同步延后到离开编辑框且中文输入法组词结束后执行，避免打字停顿时锁住输入框或替换正在编辑的内容。网络重连、页面重新可见及失败重试同样遵守此规则。手动“立即同步”和切换同步恢复码仍执行完整核对，期间暂时锁定操作。后端备份以同步状态为准；编辑中的草稿尚未自动上传。此修复仅需更新前端，无需更改后端环境变量。

辨识成功后，“开始参数辨识”按钮变灰，避免重复提交当前配置。修改辨识参数、控制器配置或数据映射后可重新辨识；上传新数据也会解锁。仅切换语言、收起侧栏、退出再进入或重复应用相同映射，不会解锁已有结果。恢复历史会话中的有效辨识结果时同样锁定；失败或超时后可重试。

结果卡片分别显示波形拟合、训练稳定性、参数准确性。留出电流/电压 NRMSE 大于 5%、初始化或估计触及边界、条件数大于 100、PANN 末段稳定性检查未通过或证据不足时显示“需复核”，并列出实际数值和阈值。末轮最佳只作记录，不再单独触发复核。没有参数真值时准确性始终“未验证”，标签变绿不代表精度提升。网页、PDF、JSON 与 Agent 说明同步；JSON 的 `assessment`、`review_reasons` 和 `diagnostics.pann.convergence` 保存分项判断与依据。旧结果缺少逐轮记录时不猜测收敛，也不修改原始历史记录；重新辨识后可获得新判据。历史限时原因仍保留。需要同时更新前后端，无需新增环境变量。

导出报告自动命名为 `月日_工况_噪声_种子_PWM来源_方法_窗口.json`，例如 `1023_A_3pct_s12_rebuilt_PANN_auto.json`。日期采用导出时的本地日期；Case10A/Case16A 等文件名提取工况 A，B 同理；`noise03` 或 `3pct` 提取为 `3pct`，`seed12` 提取为 `s12`，`clean_grid` 标为 `clean`。这些标签来自原始 CSV 文件名，不是波形噪声估计；无法识别时保留安全处理后的文件名作为工况，并使用 `noiseNA`、`seedNA`。PWM来源、计算方法及窗口依据已完成的结果：`rebuilt`/`measured`、`PANN`/`WIntegral`/`Integral`、`auto`/`1cycle`/`2cycle`/`3cycle`；积分方法的PANN窗口标为 `NA`。切换界面语言不改变命名规则，报告内容及原始文件信息保留。

左侧“实验配置”和“历史会话”标题右侧可分别折叠/展开，浏览器会记住状态。点击“新建会话”或输入框下方的重置按钮会保留旧会话并创建新会话；历史列表可随时切换，正在请求或计算时需等待完成。

对话全文、来源与工具标记、草稿、实验配置和 CSV 关联引用保存在浏览器 localStorage，原始 CSV 保存在 IndexedDB；后端 SQLite 同时保存对话及 CSV 原始字节。两端档案均不自动过期。不同会话使用不同后端会话标识，上传、清除 CSV 不清空对话。每次问答发送最近 10 条历史作为上下文（单条最多 8000 字符），完整历史仍可查看。

打开页面、保存修改后、恢复联网或点击“立即同步”时，程序合并两端消息 ID，并根据 SHA-256 校验与补齐 CSV：浏览器缺少则从后端下载，后端缺少则从浏览器上传，一端文件损坏时用另一端有效副本修复。草稿、实验配置、关联文件等元数据采用最后修改时间优先；同一时刻的冲突使用稳定排序裁决，因此同时修改同一份配置只保留一个版本，建议避免跨设备同时编辑。后端用于计算的内存缓存和任务仍为 1 小时；缓存过期后从持久副本恢复，但不会自动重跑已经失效的辨识任务。

每个浏览器首次使用会自动生成独立的 **64 位同步恢复码**，在“连接设置”中可复制。后端按恢复码的 SHA-256 隔离档案，不保存恢复码明文；生产环境还必须提供应用访问口令。恢复码不要发到聊天或提交 GitHub。换浏览器、清除本地数据或换设备后，连接同一个后端，输入原恢复码并“保存并连接”即可恢复该档案。切换恢复码会切换本地档案范围，不把原档案混入另一人的备份。旧版本本地历史首次启用时自动绑定新生成的恢复码。

“删除当前会话”删除两端对话、实验记录和 CSV，并保留不含原内容的删除标记，防止旧副本恢复已删除会话；离线删除会在重连后同步。“清除数据”保留聊天，通过文件代次同步清除 CSV，旧代次上传会被拒绝；之后主动上传新文件仍可保存。新建会话保留旧档案。旧版本 CSV 尚在后端缓存时会补存；两端均已丢失的文件不能恢复。浏览器存储失败、网络错误或后端容量不足会显示同步未完成，后端同步失败会重试；只有显示“对话、实验记录和 CSV 已同步”才说明本次双端核对完成。清除网站数据只删除浏览器副本；需要删除后端档案时使用“删除当前会话”并等待同步成功。

后端档案默认写入 `runtime/archive/archive.sqlite3`（已由 `.gitignore` 排除），可通过 `ARCHIVE_DIR` 修改。默认每份私有档案 CSV 上限 512 MiB（`ARCHIVE_MAX_BYTES`），单个 CSV 32 MiB；每个会话最多 10000 条消息、8 MiB 元数据。空间不足时拒绝新写入，不自动淘汰旧档案。SQLite 本地文件在进程重启后保留；云端是否跨部署保留取决于是否配置持久存储。

**Render 双端长期保存必须配置持久磁盘**：当前 `render.yaml` 仍为免费实例，不会自动购买或挂载磁盘。将服务改为支持磁盘的付费实例，在 Disk 中挂载 `/var/data`，设置 `ARCHIVE_DIR=/var/data/buck-archive`，再部署前后端。仅添加环境变量不等于挂载磁盘。免费实例的文件系统在重启/部署时会丢失，页面会提示后端持久存储未就绪；此时浏览器副本仍能补回，但不能作为独立长期备份。参见 [Render 持久磁盘说明](https://render.com/docs/disks)。先完成磁盘配置，再执行首次正式同步；已有 SQLite 档案迁移时应停服备份整个档案目录（包括 WAL 文件），避免复制不一致的数据库。

消息按独立条目保存，旧标签页保存或关闭不会用旧副本覆盖新增消息。未确认的列映射按草稿恢复，需点击“应用并检查数据”；辨识结果只有在文件指纹、映射和参数配置一致时才恢复。

先点击“加载已有实验示例”，再点“进入参数辨识”，确认基本信息后点“开始参数辨识”。示例是你已有的真实 PLECS Case16A CSV，默认分析 0～0.8 ms，避开 1 ms 的负载变化。无 Key 时也能上传、分析、辨识及使用明确标注的本地规则回答。

## 配置 DeepSeek

复制 `.env.example` 为 `.env`，在本地编辑器中填写：

```dotenv
DEEPSEEK_API_KEY=在这里填自己的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

随后重启后端。密钥不要填进 `frontend/config.js`，也不要提交 GitHub。默认模型依据 2026-10-15 查阅的 [DeepSeek 官方文档](https://api-docs.deepseek.com/zh-cn/) 设置；可用 `DEEPSEEK_MODEL` 更改。已实现原生工具调用，不执行模型生成的任意代码。配置 Key 之前不声称已完成真实 API 联调。

模型收到问题、最近对话、计算摘要、当前配置及检索资料。原始完整 CSV 不发送给 DeepSeek。未配置 Key 或调用失败会显式标注本地规则模式，不伪装成 AI 回答。

## 任务分类 Agent

参考 PE-GPT 的“先分类、再进入对应任务”结构，现在每条消息会先经过独立的任务分类 Agent，再交给任务处理流程：

```text
用户消息 + 最近对话 + 界面状态
    → 分类 Agent（一次独立 DeepSeek 调用，只返回任务标签）
    → 主任务 + 最多两个次任务
    → 对应提示词、上下文和工具权限
    → 知识检索 / 波形分析 / 数值计算 → 回答
```

| 主任务 | 用途 | 可启动辨识 |
|---|---|---|
| 使用指导 | CSV、连接、界面和操作步骤 | 否 |
| 公式知识 | 功率级、控制级、原理与公式 | 否 |
| 波形分析 | 实测统计与波形现象 | 否 |
| 参数辨识 | 明确要求执行 L/C/R 估计 | 是，仍检查入口、数据和配置 |
| 误差诊断 | 读取已有结果、解释误差、提出修改计划 | 否 |
| 硬件寿命 | 器件应力、选型、损耗和寿命条件 | 否 |
| 一般问答 | 其他问题与系统能力边界 | 否 |

分类 Agent 只拿到当前消息、最近 6 条历史和数据/结果/辨识入口的状态标记，不接收原始 CSV，也不能执行工具或更改参数。它使用 [DeepSeek 工具调用接口](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)返回 `route_task`，服务器验证分类枚举后分发；后续回答模型只能调用当前任务允许的工具。

“先辨识参数，再解释公式”会进入参数辨识主任务并兼顾公式知识；查看辨识结果、询问按钮位置、报告已完成、只问原理或明确拒绝执行不会启动新辨识。单独回复“继续”“好的。”及仅引用“开始参数辨识”也不作为执行请求。公式任务不依赖已上传数据仍然有效。混合任务以主任务统一决定执行权限，次任务只补充处理内容。回答旁显示任务类别；未配置 Key 显示“本地规则分类”，分类服务失败显示明确降级提示。

默认沿用 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL`，无需新增必填环境变量。可选设置 `DEEPSEEK_ROUTER_MODEL` 为分类专用模型。配置 Key 后每次问答通常增加一次短分类请求，因此会增加少量延迟和 API 用量；分类请求设置 15 秒读超时，失败时使用规则分类继续处理。这里实现的是一个分类 Agent 加各任务处理流程，并未训练多个独立模型。

## 从零部署 GitHub Pages + Render

**只将 `buck-ai-interface` 文件夹作为新仓库根目录；不要上传整个 ST4001、虚拟环境、reference 或 .env。**

1. 在 GitHub 新建仓库，例如 `buck-ai-interface`。把本项目文件提交到其 `main` 分支。`.github`、`.gitignore` 等隐藏文件也要保留。
2. 在 Render 选择 **New → Blueprint**，连接这个仓库，使用根目录 `render.yaml`。也可手动建立 Python Web Service：构建命令 `pip install -r requirements-lock.txt`，启动命令 `uvicorn backend.main:app --host 0.0.0.0 --port $PORT --workers 1`，健康检查 `/api/health`。
3. Render 环境变量设置：

   | 变量 | 值 |
   |---|---|
   | `DEEPSEEK_API_KEY` | 自己的 DeepSeek Key；留空只提供本地规则分析 |
   | `DEEPSEEK_MODEL` | `deepseek-flash`，或账户支持的模型 |
   | `APP_ENV` | `production` |
   | `APP_ACCESS_TOKEN` | Blueprint 自动生成；手动部署则设置至少 20 字符的应用口令 |
   | `CORS_ORIGINS` | `https://你的用户名.github.io`，**不包含仓库路径和结尾斜杠** |
   | `SOURCE_URL` | `https://github.com/你的用户名/buck-ai-interface`，应提供对应版本完整源码 |
   | `PYTHON_VERSION` | `3.13.5` |

4. Render 成功后记下 `https://你的服务.onrender.com`。先访问它的 `/api/health` 确认 `status: ok`。
5. GitHub 仓库 **Settings → Secrets and variables → Actions → Variables** 新建 `RENDER_API_URL`，值为上述服务地址。它是公开地址，不是 Secret。不要在 GitHub Variables 中放 DeepSeek Key。
6. GitHub **Settings → Pages → Source** 选择 **GitHub Actions**。在 Actions 手动运行 `Deploy interface to GitHub Pages`。该流程只发布 `frontend/`。

## 三列 CSV：固定已知 R 识别 L、C

PWM 列为可选项，可与时间、电流、电压一起放在同一 CSV 中上传。新会话默认“自动：有 PWM 列则使用，否则重建”：映射了 PWM 列时使用实测开关信息，没有映射时显示已知控制器配置，须用户确认匹配后才能重建，不能把任意三列文件自动当作已知电路。也可手动指定“CSV 实际开关状态”或“三列 CSV · 已知控制器重建”；历史会话保留原选择。

重建模式锁定 LC，用户填写已知负载 R，不估计 R；默认仍使用 PANN，没有 PyTorch 时可选择抗噪加权积分。上传新的 CSV 后须重新确认控制器配置。自动选择在前端根据已应用的列映射解析为 `measured` 或 `controller` 后提交，后端继续校验对应输入与电路条件；无效的实测 PWM 不会被静默忽略或改用重建。

重建区域提供默认 Buck 功率级与 RC 控制器接线图，点击“放大 / 编辑”或图上的参数可修改数值。默认 R1=11 kΩ、R2=85 kΩ、R3=120 kΩ、R4=47 kΩ、C2=1.1 nF、C3=2.7 nF，运放增益 10⁶、参考 5 V，调制增益 0.25、占空比限幅 0.1～0.9，100 kHz 上升锯齿载波且 t=0 相位为零，C2/C3 初始电压均为 0。编辑后的元件、增益、限幅、相位和初态通过 `options.controller` 传入重建及闭环验证；频率仍取 `options.frequency_hz`。拓扑固定，不支持任意接线。保存修改后清除旧结果并要求重新确认。L、C 保持待辨识量，R 为用户已知负载。

支持上传 PNG/JPG/WebP（最大 5 MB）替换参考图，压缩后随会话字段保存并参加双端同步；不会自动读图、提取参数、传给聊天模型或改变接线。恢复默认图只更换图片，恢复默认参数在编辑器中单独操作。CSV 仍须从 t=0 开始，区间结束于 1 ms 前且负载恒定，默认建议 0～0.8 ms。每次最多 100000 个控制器计算步，并检查控制器在该 Euler 步长下的稳定性；不满足条件时拒绝辨识。电路、载波、控制器初态不匹配时不能直接确认。

后端 `controller.py` 按旧 `closed_loop_identification.py` 的 RC 控制器方程及当前参数，用训练段电压重建 PWM 与取样支路电流；重建和 PANN 每周期 500 步，默认 100 kHz 时为 20 ns，其余窗口状态联合估计机制保留。积分初始化与 PANN 都扣除取样支路电流。固定拟合后的 L/C 和用户给定 R，从起点连续进行四状态自主闭环验证：控制器使用预测电压，后续不注入测量状态、留出电压或实际 PWM。留出误差在原 CSV 时间点计算。控制器配置、输入来源和验证方式写入结果与报告；不将重建信号标记为实测 PWM。

辨识任务按顺序执行：检查配置 → 重建 PWM 开关信息 → 参数初始化 → PANN 训练（选择加权积分时跳过）→ 波形验证。任务接口的 `stage` 返回当前阶段，中英文界面同步显示；快速阶段可能在两次轮询之间完成。结果与导出报告的 `diagnostics.pwm_reconstruction` 记录重建区间、实际计算步长（默认 20 ns）、采样点数及上升/下降沿数，界面显示重建已完成。重建只使用训练段；留出测量不参与重建或参数训练。

这是对指定电路的三列数据支持，不是通用未知控制器辨识。含噪电压会影响重建边沿；已有 Case15/16 的真实 PWM 抗噪结果不能直接作为此模式的精度证据。低波形误差不保证参数准确。测试只使用真实 PLECS 示例的前三列并移除 PWM；参数真值只用于测试结束后的断言，不进入拟合器。

## 计算边界

当前是**理想非同步 Buck**，R 表示**恒定等效负载电阻**，不表示电容 ESR 或绕组电阻。默认模型忽略反馈取样支路、死区、器件压降及寄生，与你 Case15/16 的完整闭环算法不是同一验证协议。积分回归是新实现的轻量基线，PANN 是上游代码的新适配；没有把旧实验数值冒充新结果。

选择恒定负载且动态足够的区间。跨负载突变的记录可能给出“需复核”；不要把输出参数直接视为真实元件值。可辨识性和 5% 归一化波形误差阈值只作工程筛查，并非统计置信度。含噪情况下积分回归也可能有偏，需要另做噪声、多初值及独立工况验证。

实测 PWM 模式属于**同一记录后段留出、实测 PWM 驱动**，不是自主闭环验证。已知控制器重建模式使用同一记录后段的自主闭环预测；两者都不是独立工况验证。未提供独立真值，不计算参数真实误差。没有实现真实硬件剩余寿命预测；寿命问答说明需要的型号、热条件、工况与适用厂商模型。

服务使用内存暂存数据/任务，重启或休眠后需重新上传；必须保持 `--workers 1`，多实例部署需要引入共享存储和任务队列。当前适合个人课题与受控演示。

## 可选 PANN

界面的“计算方法”提供两个选项，新会话默认使用 PANN；后端未安装 PyTorch 时，界面自动使用抗噪加权积分。历史会话保留用户已选择的方法。API 省略方法时也默认 PANN，未安装依赖会明确报错，调用方可显式指定 `weighted_integral`：

| 方法 | 行为 | 依赖 |
|---|---|---|
| 抗噪加权积分 · 直接辨识 | 直接采用加权积分估计，不运行 PANN；连续验证使用首个测量状态的非负投影 | 默认轻量依赖即可 |
| PANN · 物理网络微调 | 从同一加权积分初值继续优化窗口状态和参数，不保证更准确 | 需要 PyTorch |

两者均按时间分训练/留出并连续验证；PANN 联合模式的验证初态来自训练段估计，因此波形误差对比也包含初态策略的影响。切换方法会使旧结果失效，选择随会话保存。新加权积分使用独立的 `weighted_integral` 标识；旧 `integral` API 仍保留原算法供复现，旧会话恢复到新选择时不会把旧结果冒充新方法结果。

默认 Render 只安装轻量依赖。若需要 PANN，在具备足够内存的后端环境运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-pann.txt
```

重启后端，页面会启用 PANN 选项，并显示窗口初值、窗口长度和训练轮数设置：

- 默认从含噪训练数据**联合估计每个窗口的初始电流、电压和共享参数**；保留“固定测量初值”作成对对照。状态非负，含噪训练目标不截断；不使用干净初值。
- L/C/R 初值使用训练段的**端点零权重积分估计**：在 2/5/10 周期窗口上使用 `φ(u)=u²(1−u)²`，分部积分把含噪端点差值换成 `−∫φ′x dt`。PWM 保持零阶保持；正值边界、动态和 C/R 条件数检查仍有效。界面的抗噪加权积分方法直接采用这组参数；选择 PANN 才继续微调。这是本接口新增的方法，不是原 Case15 的算法。
- PANN 窗口遍布完整训练区间，最多 40 个不重叠窗口，实测 PWM 模式每周期 200 个 Euler 步，控制器重建模式每周期 500 步。默认“自动”：仅根据训练段局部噪声估计，任一通道噪声达到其 RMS 的 0.5% 时优先 3 周期，否则 1 周期；短训练段缩短窗口以保留至少 4 个窗口。这是可检查的经验规则，不是最优窗口或抗噪保证；可手选 1/2/3 周期对照，报告记录实际长度与选择依据。不会把长记录截成最前面的 50000 点。
- 联合模式先固定参数预热 50 轮窗口状态，再新建优化器进行默认 100 轮联合更新（可选 10–300），避免把初始状态误差带进参数优化器的历史梯度；固定测量模式不预热。预热本身不能消除短窗口的 C 偏差。**训练不设时间上限**：已移除训练循环的 120 秒限制、`PANN_PYTHON` 解释器桥接的 180 秒超时以及前端最多 600 次的轮询限制。正常运行会完成设置的轮数，停止原因仍记录为 `epoch_budget`；训练发散或运行错误仍报告失败。保存**同一最小含噪训练损失轮次**的参数和全部窗口状态。报告记录起点、步长、初始参数、最终状态、噪声估计、预热/最佳轮次及停止原因；最佳轮次仅作记录，是否需复核由独立的末段稳定性判据决定；不声称数学收敛或参数准确。
- 排队和运行中的任务及其数据不会因临时缓存 TTL 被清理；结束后从完成时刻重新计算临时缓存保留时间。前端仍保留单次网络请求超时以提示断网，这不会终止后端训练；聊天 API、数据库等待和测试脚本超时不属于训练限时。旧报告中的 `time_budget` 是历史事实，不改写。取消代码内限时不改变托管平台自身的重启或资源限制。更新前端和后端后生效，无需新增环境变量。
- 连续前向验证只在所选区间起点使用首窗口估计状态，后续和留出段均不重置。参数真值和留出测量不参与初值/轮次选择。**低训练损失不保证参数准确，PANN 微调也可能比初始化偏差更大。**

本地 Case14 的干净初值替换只用于诊断；Case15/16 支持尝试联合状态估计，但其完整控制/反馈模型和自主闭环验证没有搬入当前接口。参考汇总与 SHA-256 见 [噪声实验来源](backend/knowledge_base/noise_evidence.json)。Case17 含噪辨识尚未完成，不作为验证成功证据。

## 参数真值对照

结果卡片显示“预测电感 L / 预测电容 C”。辨识完成后可输入真实电感（μH）和真实电容（μF），点击“计算相对误差”，使用完整精度预测值按 `abs(预测值 / 真实值 - 1) × 100%` 分别计算 L、C 误差。真实值必须有限且大于 0，只用于结果对照，不参与训练、轮次选择或波形误差检查。修改真实值立即清除旧误差，需重新点击计算；更换数据或辨识配置会清除对照，避免套用到另一结果。有效对照随会话元数据保存，恢复同一有效结果时显示；导出 JSON/PDF 包含真值和相对误差，PDF 从预测值及用户真值重新计算。前端“参数准确性”标为已对照用户提供真值，不声称真值已独立核验。

真值对照计算完成后，提问或点击“让助手分析结果”会携带与当前结果绑定的 L/C 真值。后端核对会话、数据、配置及结果，再用完整精度预测值重新计算误差；DeepSeek 工具上下文与本地后备分析均可引用。修改真值后尚未重新计算、或更换结果时不沿用旧对照；不改写原始辨识任务。工具上下文及新导出的 JSON 中，`parameter_error` 与 `parameter_comparison` 均包含用户真值、`relative_error_pct` 和来源，避免保留误导性的 `null`。本更新需同时部署前后端，无新增环境变量。

## PANN 末段稳定性判据

`two-window-stability-v2` 是待实验校准的试用规则，不是数学收敛证明，也不是参数准确性的保证。训练仍完成指定轮数，不提前停止。旧 `tail-stability-v1` 报告按原规则显示版本和阈值，不自动改写历史。

- 仅使用参数训练后逐轮记录，排除初值预热和第 0 轮。每轮完成后检查一次：前后两个不重叠窗口各 20 轮；相邻检查整体滑动一轮。
- 平均训练损失相对变化为 `abs(后窗口均值 - 前窗口均值) / max(前窗口均值, 1e-12)`，严格小于 0.1% 通过。接近零时允许平均损失绝对变化严格小于 `1e-10`，是否使用绝对容差会记录并展示。
- 最近 20 轮 L、C 各自的 `(最大值 - 最小值) / 窗口均值` 严格小于 0.1%；联合估计 R 时对 R 使用相同条件，固定 R 不参与检查。
- 训练结束时连续 3 次检查通过才标记“训练已稳定”。第 40 轮首次可检查，第 42 轮最早可确认；失败会清零连续计数，历史记录不足时报告证据不足。
- 保留独立留出波形误差检查。训练稳定但留出 NRMSE 未达标时明确显示“训练已稳定，但拟合未达标”。没有参数真值时准确性始终未验证。
- 最佳轮次及返回最佳结果与末段差异仅作诊断记录，不再额外触发本试用规则。按平均损失比较可能掩盖窗口内周期性震荡，应在实验中校准并结合完整逐轮曲线判断。

助手撰写分析与报告时忽略“最佳结果位于末轮”，不再引用这条警告或据此建议增加轮数。发送给助手的结果副本移除此项记录及对应旧复核原因，原始任务和完整 JSON 仍保留诊断记录；实际稳定性、留出误差、边界和真值对照照常分析。此调整需更新后端。

默认助手结果分析采用精简形式：预测参数、用户真值及参数相对误差、简短结论与必要建议。不再罗列或展开“其他过程事实”“数据和波形事实”，不重复窗口、噪声、状态修正、条件数、PWM 重建过程或波形统计。诊断数据仍用于内部判断，影响结论的异常只作简短说明；用户明确追问某项细节时再解释。本地后备回答同步精简，原始数据及导出报告结构不受影响。

分析正文不再附加“明确无法给出的结论”等例行限制清单或“如果你希望，我可以……”结尾邀请。缺少有效真值对照时只标注“未计算参数相对误差”，已有对照时展示用户真值及实际误差；仍不编造准确性或泛化结论。用户明确询问技术边界时再解释，实际验证未通过等异常仍简短保留。中英文提示规则与本地后备回答同步更新，需要重新部署后端。

## 对话 Markdown 显示

AI 正文回复请求的 `max_tokens` 为 `8000`，任务分类单独使用 `250`。这是输出 token 上限，不是字数或训练时间限制；修改后须重新部署后端，无需新增环境变量。历史上下文仍按最近 10 条、单条最多 8000 字符发送，与本次回复的输出 token 上限不同。

Agent 回复支持 Markdown 标题、加粗/斜体、删除线、列表、引用、表格、链接和代码块。代码块提供中英文“复制代码”按钮；宽表格与长代码在消息内部横向滚动。用户输入保持纯文本，历史会话、后续对话上下文和 JSON 中保存原始 Markdown，刷新或切换会话时重新渲染。兼容模型单独一行 `**标题 **` 的尾部空格，不改写原始记录或代码块。渲染禁用原始 HTML、危险链接和外部图片加载；解析库随前端发布，无需 CDN、后端依赖或新的环境变量。

## PDF 与 JSON 双文件导出

点击“导出报告（PDF + JSON）”，会下载两份相同文件名主体的文件，例如 `1023_A_3pct_s12_rebuilt_PANN_auto.pdf` 和 `.json`。命名仍依据已完成的辨识结果，日期使用导出时的本地日期。

- PDF 面向阅读和汇报，使用点击导出时的界面语言，包含数据与方法、参数及固定 R 的说明、留出误差、测量与预测波形、实际复核原因及建议。它整理已有结果，不重新辨识、不调用 DeepSeek，也不把波形误差当成参数真实误差。
- JSON 保留完整实验数据、诊断、波形及对话，格式与原有导出一致。PDF 从同一份结果快照生成，支持恢复后的历史结果，不要求临时任务仍在后端内存中。
- 浏览器可能拦截连续下载；结果卡片下方提供“下载 PDF”和“下载 JSON”链接，可分别补下。若后端连接失败或尚未更新，JSON 仍可下载，页面明确提示 PDF 失败；更新后端后重新导出即可。

后端新增受现有应用口令保护的 `POST /api/reports/pdf` 接口。请求中的波形长度、数值及结构经过校验，响应不缓存；不读取其他会话或外部图片。PDF 生成依赖 `reportlab`，已加入 `requirements.txt` 和 `requirements-lock.txt`；**本次需要同时更新 GitHub Pages 前端和 Render 后端，Render 重新构建安装依赖，无需新增环境变量**。本地更新依赖可运行 `.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt`。
